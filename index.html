01

Why add a policy gate?

A valid plan can still break a rule your team depends on, and the pipeline is the last place that can stop it.

Review misses things
An empty owner tag, an oversized volume, a destroy hidden inside a replacement.
After apply is too late
Cleanup and rollback, for something the plan already showed you.
Scripts rot
Every one-off check carries its own parsing, exit codes and upkeep.
02

Put Tirith between plan and apply.

Tirith fits into the pipeline you already have. Your IaC tool produces the plan, Tirith checks it, and the exit code tells the pipeline whether to continue.

  1. 1

    Your IaC tool plans

    OpenTofu or Terraform exports the proposed change as plan.json.

  2. 2

    Tirith reads the plan

    The plan provider finds the resources and attributes each policy asks for, from either tool.

  3. 3

    Policies test the change

    JSON conditions check each matching value and produce one verdict.

  4. 4

    CI continues or stops

    A pass moves on to apply. A failure explains the rejected values and, with fail-on-error, exits 3.

03

Add Tirith to your pipeline

Three pieces make the gate work, and they are the same three everywhere: a policy, the plan as JSON, and Tirith running with fail-on-error. Only the way you invoke it changes between platforms.

  1. 1

    Commit a policy

    Put one or more JSON rules under .tirith/policies/.

  2. 2

    Export the plan

    Run tofu show -json tfplan > plan.json (or terraform show).

  3. 3

    Run the gate

    Set fail-on-error so a failed policy blocks the job.

.github/workflows/plan.yml
permissions:
  contents: read
  pull-requests: write
  checks: write

steps:
  - run: terraform plan -out=tfplan -input=false

  - uses: StackGuardian/tirith-iac-governance-action@v2
    with:
      plan-file: tfplan
      fail-on-error: true

The Action wraps the CLI and adds the pull-request comment and check run.

Open the GitHub demo →
  • OpenTofu works identically — swap terraform for tofu; the plan JSON is the same
  • Policies are JSON files committed under .tirith/policies
  • On GitHub the Action adds the pull-request comment and check run, which need the two write permissions
  • Without fail-on-error, Tirith reports findings but does not block the job
